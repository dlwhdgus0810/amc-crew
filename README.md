# 🎯 Kansas Korean

친구들끼리 **취미 모임**을 만들고 같이 놀 사람을 모으는 앱.

- **영화 🎬** — The Odyssey (AMC Town Center 20) 회차 맞추기: 가능한 회차를 선택하면 같은 회차끼리 자동 그룹 매칭
- **피클볼 🥒 · 볼링 🎳 · 축구 ⚽** — 날짜/시간/장소를 정해 모임 포스트를 올리고, 다른 사람이 참가 등록
- **구독·알림 🔔** — 취미를 구독하면 새 모임이 올라올 때 인앱 알림 수신

## 페이지

| 경로 | 설명 |
|------|------|
| `/` | 홈 — 취미 카테고리 선택, 구독 토글, 카카오 로그인/닉네임 설정 |
| `/c/pickleball` 등 | 취미별 모임 피드 — 모임 만들기, 참가/취소, 삭제(작성자·관리자) |
| `/notifications` | 인앱 알림 목록 (진입 시 자동 읽음 처리) |
| `/movie` | 카카오 로그인 후 가능한 영화 회차 선택·저장 |
| `/movie/groups` | 영화 그룹 매칭 결과 — 2명 이상 겹친 회차가 위에 표시 |
| `/admin` | 영화 스케줄 편집 (회차 추가/삭제, AMC API 새로고침). `ADMIN_KEY` 필요 |

## 저장소 구조

- **Postgres (Neon + Drizzle)** — 사용자 프로필(닉네임), 모임 포스트, 참가, 구독, 알림
- **Upstash Redis** — 영화 스케줄·회차 선택 (기존 기능 전용)

## 배포하기 (Vercel + Upstash)

1. **GitHub에 푸시**
   ```bash
   cd kansas-korean
   git init && git add -A && git commit -m "init"
   # GitHub에 새 repo 만든 뒤:
   git remote add origin https://github.com/<유저명>/kansas-korean.git
   git push -u origin main
   ```

2. **Vercel에서 Import**
   - [vercel.com/new](https://vercel.com/new) → 방금 만든 repo 선택 → Deploy
   - 프레임워크는 Next.js로 자동 인식됩니다.

3. **Upstash Redis 연결** (영화 기능용)
   - Vercel 프로젝트 → **Storage** 탭 → **Create Database** → **Upstash Redis** (무료 플랜 충분)
   - `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` 또는 `KV_REST_API_URL`/`KV_REST_API_TOKEN` 어느 이름으로 주입돼도 인식합니다.

3-1. **Neon Postgres 연결** (모임/구독/알림/프로필용)
   - Vercel 프로젝트 → **Storage** 탭 → **Create Database** → **Neon Postgres** (무료 플랜 충분)
   - 연결하면 `DATABASE_URL`(또는 `POSTGRES_URL`) 환경변수가 자동 주입됩니다.
   - 로컬에서 테이블 생성: `.env.local`에 `DATABASE_URL`을 넣고 (`vercel env pull`로 받아도 됨)
     ```bash
     npm run db:push   # lib/db/schema.ts 기준으로 Neon에 테이블 생성 (스키마 변경 때마다 재실행)
     ```

4. **환경변수 설정** (Vercel → Settings → Environment Variables)
   - `ADMIN_KEY` — 관리자 페이지(영화 스케줄 편집)용 비밀 키 (아무 문자열)
   - `ADMIN_KAKAO_ID` — 관리자로 인정할 카카오 회원번호 (쉼표로 여러 명 가능). 로그인 후 `/api/auth/me`의 `user.id`로 확인
   - `KAKAO_REST_API_KEY` — 카카오 로그인용 REST API 키 (아래 "카카오 로그인 설정" 참고)
   - (선택) `KAKAO_CLIENT_SECRET` — 카카오 앱에서 Client Secret을 활성화한 경우
   - `AUTH_SECRET` — 세션 쿠키 서명용 비밀 키 (`openssl rand -base64 32` 등으로 생성)
   - (선택) `AMC_VENDOR_KEY`, `AMC_THEATRE_ID` — 아래 "AMC API 연동" 참고

5. **Redeploy** 후 나온 URL을 친구들한테 공유하면 끝!

## 카카오 로그인 설정

이름 입력 대신 **카카오 로그인만** 지원합니다. 선택 데이터는 카카오 회원번호 기준으로 저장되고, 표시 이름은 카카오 닉네임을 사용합니다.

1. [developers.kakao.com](https://developers.kakao.com) → **내 애플리케이션** → 앱 추가
2. **앱 설정 → 플랫폼 → Web** 에 사이트 도메인 등록 (`http://localhost:3000`, 배포 URL)
3. **제품 설정 → 카카오 로그인** 활성화 후 Redirect URI 등록:
   - `http://localhost:3000/api/auth/callback` (로컬)
   - `https://<배포 도메인>/api/auth/callback` (프로덕션)
4. **제품 설정 → 카카오 로그인 → 동의항목** 에서 **닉네임(profile_nickname)** 을 필수 동의로 설정
5. **앱 설정 → 앱 키** 의 **REST API 키**를 `KAKAO_REST_API_KEY` 환경변수에 입력
6. (권장) **제품 설정 → 카카오 로그인 → 보안** 에서 Client Secret 활성화 후 `KAKAO_CLIENT_SECRET`에 입력

## 예정 / 지난 모임 기준

모임은 **종료 시각이 지나고 1시간 뒤**에 "지난 모임"으로 내려갑니다
(`lib/dates.ts`의 `PAST_GRACE_MINUTES`). 끝나자마자 접히면 후기 댓글을 달기 번거로워서 둔 유예예요.

판정은 서버가 앱 시간대(`APP_TIMEZONE`, 기본 `America/Chicago`) 기준으로 하고
`PostView.isPast`로 내려주므로, 다른 시간대에서 열어도 결과가 같습니다.

## 카테고리 제안

사용자가 `/suggest`에서 새 취미 카테고리를 제안할 수 있습니다 (홈 캐러셀 아래 링크).

- 제출 항목: **이름 · 색상 · 부제목**, 그리고 선택으로 **원하는 기능**
  (예: 무비나잇의 TMDB 영화 검색처럼 이 카테고리에 붙었으면 하는 연동)
- 색상은 추천 팔레트에서 고르거나 직접 지정하고, 홈 카드와 같은 모양으로 실시간 미리보기를 보여줍니다
- 제안이 들어오면 `ADMIN_KAKAO_ID`의 관리자에게 인앱 + 카톡 알림이 갑니다
- 관리자는 `/admin` 상단에서 승인/반려하고 답변을 남길 수 있고, 결과는 제안자에게 알림으로 갑니다
- **승인은 알림까지만 처리합니다.** 실제 카테고리 추가는 `lib/categories.ts`에 항목을 넣고 배포해야 반영돼요

## 정기 모임

모임 만들기에서 **매주 반복**을 체크하면 고른 날짜의 요일이 반복 요일이 됩니다
(예: 8/1 토요일 선택 → 매주 토요일).

- 첫 회차는 바로 열리고, 이후 회차는 **매일 아침 크론이 7일 앞까지 미리 생성**합니다
- 생성된 회차는 평범한 모임이라 참가·정원·댓글·공유·캘린더·리마인더가 그대로 동작해요
- 회차가 열릴 때 구독자에게 "이번 주 모임" 알림이 나가 주간 참가 확인 역할을 합니다
- 정기 모임은 **작성자도 참가를 취소**할 수 있어요 ("매주 열리지만 이번 주는 못 감")
- 카드의 **반복 중단**은 규칙만 끄고 이미 열린 회차는 남깁니다. 개별 회차는 삭제로 취소하세요

## 밖으로 나가는 링크 주소

카톡 알림·공유·캘린더 링크는 `NEXT_PUBLIC_SITE_URL`(예: `https://www.kansaskorean.com`)을 씁니다.
설정하지 않으면 요청이 들어온 호스트를 그대로 쓰기 때문에, 로컬에서 만든 링크에 `localhost`가
박히거나 vercel.app으로 들어온 요청의 알림이 vercel.app을 가리키게 됩니다.
**Vercel 환경변수에 꼭 넣어주세요.** (로그인 redirect_uri는 실제 접속 호스트를 써야 하므로 이 값과 무관합니다.)

개발 중에는 실제 카카오톡 발송을 건너뜁니다 — 진짜로 보내보려면 `KAKAO_MEMO_IN_DEV=1`.

**도메인을 바꾸면 카카오 콘솔에도 등록해야 합니다.** 카카오는 메시지 링크의 도메인이
**[제품 링크 관리] > [웹 도메인]** (예전 이름: 앱 설정 > 플랫폼 > Web > 사이트 도메인)에
등록돼 있지 않으면, **등록된 다른 도메인으로 조용히 바꿔서** 메시지를 만듭니다. 오류가 나지 않고
링크만 엉뚱해지기 때문에 코드를 아무리 봐도 원인이 보이지 않습니다.
로그인 Redirect URI는 별개 설정이라 이게 빠져 있어도 로그인은 멀쩡히 됩니다.
목록에 `localhost`를 남겨두지 마세요 — 미등록 링크가 전부 그리로 치환됩니다.

## 카카오톡 알림 (나에게 보내기, 선택)

새 모임·변경·취소 알림을 인앱 알림에 더해 각자의 **카카오톡 "나와의 채팅"** 으로도 보냅니다.

1. 카카오 콘솔 → **동의항목**에서 **카카오톡 메시지 전송 (talk_message)** 을 **선택 동의**로 추가
   (동의 목적 예: "모임 생성/변경/취소 알림을 카카오톡으로 전달")
   → **필수 동의로 잡으면 안 됩니다.** 거부한 사용자가 로그인 자체를 못 하게 됩니다.
2. 사용자는 **프로필 → 카카오톡 알림**에서 언제든 켜고 끌 수 있습니다
   - **켜기**: 카카오 추가 동의 화면을 거친 뒤 확인 메시지 1건이 "나와의 채팅"으로 도착합니다
   - **끄기**: 카카오에서 `talk_message` 동의를 실제로 철회합니다 (인앱 알림은 계속 받습니다)
   - **상태 확인**: 카카오에 현재 동의 상태를 다시 물어봅니다
3. 동의하지 않은 사용자는 기존처럼 인앱 알림만 받습니다 (기능 전체가 선택 사항)

토큰은 로그인 시 users 테이블에 보관되고, 만료되면 리프레시 토큰으로 자동 갱신됩니다.
동의 상태(`users.kakao_talk_message`)는 ① 매 로그인마다 카카오 `/v2/user/scopes` 조회로 확정되고
② 발송이 동의 부족(403/-402)으로 실패하면 자동으로 "미동의"로 정정됩니다 —
사용자가 카카오톡 설정에서 직접 철회한 경우도 앱 화면에 반영됩니다.
"나에게 보내기"는 비즈니스 인증 없이 사용 가능한 API입니다 (친구에게 직접 발송은 심사 필요).

## 로컬에서 실제 DB 건드리지 않기

`npm run db:push`를 하려면 `.env.local`에 진짜 `DATABASE_URL`이 필요합니다. 그런데 그걸 넣어둔 채
dev 서버를 띄우면 로컬 테스트가 그대로 서비스 데이터에 씁니다 — 실제로 두 번 사고가 났습니다.

그래서 **개발 환경에서는 원격 DATABASE_URL을 무시하고 인메모리(PGlite)로 붙습니다.**
로그에 이렇게 남습니다:

```
[db] 개발 환경이라 원격 DATABASE_URL을 무시하고 인메모리(PGlite)로 붙습니다.
     실제 DB에 붙이려면 ALLOW_PROD_DB=1 을 함께 주세요.
```

정말 실제 데이터를 봐야 할 때만 `ALLOW_PROD_DB=1`을 함께 주세요.
`drizzle-kit`은 이 경로를 거치지 않으므로 `db:push`는 그대로 동작합니다.

## 정산

모임 상세(`/p/<id>`)에서 참가자 누구나 정산을 시작할 수 있고, **시작한 사람이 돈을 받는 사람**이 됩니다.

- 항목마다 **참가자 전원**이 나눠 낼지, **고른 사람만** 낼지 정합니다 (내기에서 진 사람들처럼)
- 금액은 **총 금액**을 넣습니다. 머릿수로 나누는 계산은 읽을 때 하므로, 나중에 사람이 빠지면 몫도 따라 바뀝니다
- **이 앱에 없는 사람**도 인원수로 더할 수 있습니다. 머릿수에만 들어가고 청구는 하지 않아서,
  참가자 몫의 합은 총액보다 작습니다 (그 차액은 받을 사람이 알아서 받습니다)
- 저장하면 각자에게 **자기 금액이 적힌 알림**이 갑니다 (인앱 + 카톡 + 앱 푸시). 받는 사람 본인에겐 가지 않아요
- 받을 계좌는 **카카오톡 본문에만** 싣습니다. 인앱 알림과 푸시는 눌러서 정산 카드로 가고
  거기에 금액이 채워진 버튼이 있으니, 목록에 계좌가 늘어져 있으면 정작 읽어야 할 금액이 묻힙니다
  (카톡도 버튼이 아니라 본문에 넣습니다 — 버튼 주소는 카카오에 등록된 도메인이어야 하고,
  등록되지 않은 주소는 조용히 다른 도메인으로 바뀝니다)
- **받는 사람에게는 정산 카드에 본인 계좌**가 보입니다. 앱 밖 인원이 있으면 Venmo 아이디 자체가
  전달용 링크가 되고 옆 버튼이 "링크 복사"로 바뀝니다 — 긴 주소를 한 줄 따로 늘어놓지 않습니다
- 항목을 채우는 동안 **1인당 얼마인지 실시간으로** 보여주고, 보내기 전에 **계산 결과를 한 번 더 확인**받습니다
  (알림은 되돌릴 수 없어서 숫자를 눈으로 볼 기회를 둡니다)
- 계좌가 하나도 없으면 그 확인 화면에서 함께 받고, 넣으면 프로필에도 저장됩니다
- 앱 밖 인원에게 전달할 Venmo 링크는 **자체 단축 주소**(`/v/<code>`)로 나갑니다.
  금액이 박힌 venmo.com 주소는 96자까지 늘어나 알림 본문에서 읽기 어렵고, 우리 도메인은
  카카오에 등록돼 있어 주소가 바뀔 걱정도 없습니다. 열리는 시점에 금액을 계산하므로
  **정산을 고치면 이미 보낸 링크도 새 금액을 가리킵니다.**
- **받을 사람이 관리자면 본인에게도 사본**이 갑니다 — 내용은 "{n}명에게 총 {금액}" 요약이라
  스스로에게 청구하는 문구가 되지 않습니다 (알림 경로 점검용)
- 프로필 → **받을 계좌**에 Venmo/Zelle을 넣어두면 정산 화면에 보내기 수단이 붙습니다
- 카테고리 피드의 모임 카드에도 **참가한 사람에게만** 정산 버튼이 뜹니다 (낼 금액이 있으면 금액까지)

**정산은 참가자와 관리자만 볼 수 있습니다.** 누가 얼마를 빚졌는지와 받을 계좌가 담기므로,
참가하지 않았거나 로그인하지 않은 사람에게는 조회가 404이고 목록 응답에서도 `settle`이 null입니다 —
정산이 있다는 사실 자체가 나가지 않습니다. 모임 상세에서도 섹션이 그려지지 않습니다.

**돈은 앱을 거치지 않습니다.** Venmo 딥링크가 받는 사람·금액·메모를 채운 채로 Venmo를 열어줄 뿐이고,
확인은 Venmo 안에서 본인이 누릅니다. 앱이 돈을 보관하거나 옮기면 자금이체업 문제가 생깁니다.
(딥링크 형식은 Venmo가 문서로 보장한 규격이 아니라 바뀔 수 있습니다.)
**Zelle은 공개 API도 딥링크도 없습니다** — 열어줄 링크를 만들 수 없어서, 등록해 둔 전화번호나
이메일을 화면에 띄우고 복사 버튼만 제공합니다. 보내는 건 각자 은행 앱에서 합니다.

금액은 **센트 정수**로만 다룹니다(`lib/money.ts`). 나머지 센트는 버리지 않고 앞사람부터 1센트씩 얹어,
각자 금액의 합이 항상 원금과 같습니다 ($10을 셋이 나누면 3.34 / 3.33 / 3.33).

## 익명 카테고리

`Category.anonymous`를 켠 카테고리(별보러가자)에서는 **아무 이름도 나가지 않습니다**. 연 사람,
명단, 댓글이 전부 「익명」이고 얼굴(아바타)과 주최 뱃지도 빠집니다. 보고 있는 본인만 자기를
알아봅니다 — 명단에서 「익명 (나)」로 보이고, 참가/수정/삭제 버튼이 그걸로 판단합니다.

**이름만 가리는 것으로는 부족합니다.** 이름을 「익명」으로 바꿔 놓고 회원번호를 그대로 내보내면
개발자 도구를 여는 것만으로 누구인지 읽힙니다(친구 목록·관리자 명부에 같은 번호가 있습니다).
그래서 `buildViews`가 남의 `authorId`·`coHost.id`·참가자 `id`·댓글 `userId`를 지웁니다.

이름이 새는 통로도 함께 닫습니다. `anonymous`를 켜면 자동으로:

| 막는 것 | 왜 |
|---|---|
| 정산 | 「지훈 $12 · 민서 $8」처럼 금액 옆에 명단을 통째로 폅니다 |
| 명단에서 친구 요청 · 대신 넣기 | 요청을 보내는 순간 상대가 누구인지 알게 됩니다 |
| 「친구가 참가했어요」 알림 | 이름을 가려도 **받은 사람이 자기 친구 목록과 맞춰 보면** 좁혀집니다 |
| 순위표(호스팅·참여) 집계 | 「전부 익명」이라 해 놓고 다녀온 만큼 점수가 오르면 앞뒤가 안 맞습니다 |
| `sharesMeetup` 자격 | 세면 「저 사람 거기 있었나?」를 403/200으로 읽어내는 창구가 됩니다 |

댓글은 체크칸이 사라지고 **서버에서** 무조건 익명으로 저장됩니다 — 화면이 아니라 라우트가 정합니다.

임시 카드는 지우지 않고 관리자 화면에서 **목록에 내립니다**(`hidden_categories`). 카테고리는 코드에
그대로 있고 주소로도 열리므로, 그날 남긴 사진과 댓글이 사라지지 않습니다.

## 이름

한 사람의 이름은 **보는 사람의 언어에 따라 달라집니다**. 정하는 곳은 `resolveDisplayName`
(`lib/store.ts`) 한 군데입니다.

| 보는 언어 | 고르는 순서 |
|---|---|
| 한국어 | 닉네임 → 카카오 닉네임 |
| 그 밖(English·Español) | **영어 이름** → 닉네임 → 카카오 닉네임 |

이름이 카카오 닉네임에서 오다 보니 명단이 거의 한글인데, 한국어가 아직 익숙하지 않은 회원에게는
그게 읽을 수 없는 글자의 나열입니다. 영어 이름은 프로필에서 각자 적습니다(로마자와 `- . '` 만,
30자까지). 안 적으면 예전과 똑같습니다.

**영어 이름이 닉네임보다 앞입니다.** 닉네임도 본인이 정한 이름이지만 그것 역시 한글인 경우가
대부분이라, 뒤에 두면 이 기능이 하려던 일을 못 합니다.

**실명만 쓰는 모임(`allow_nicknames=false`)에서도 영어 이름은 그대로 나옵니다.** 그건 다른 사람
행세가 아니라 같은 이름을 읽을 수 있는 글자로 적어 둔 것이기 때문입니다.

users 행에서 이름을 만들 때는 `nameOf(row, fallback, locale)`를 씁니다 — 어느 칸이 이름을
만드는지 아는 곳을 하나로 두려는 것입니다. 이름에 쓰이는 칸이 하나 늘 때 열대여섯 군데를 손으로
고치다 하나를 빠뜨리면, 타입은 통과하고 그 화면만 조용히 예전 이름으로 남습니다.

주의할 곳이 둘 있습니다.

- **담아 두는 질의(`unstable_cache`)에서는 이름을 정하지 않습니다.** 순위표가 그렇습니다 —
  담기 전에 이름을 정하면 그 표를 처음 연 사람의 언어가 5분 동안 모두에게 남습니다. 그래서
  캐시에는 이름의 재료만 담고(`RankSeed`), 이름은 화면을 그리는 자리에서 고릅니다(`rankNames`).
- **알림 문구 속 이름은 미리 문자열로 굳히지 않습니다.** 알림은 받는 사람마다 그 사람의 언어로
  만들어지는데(`buildNotice`), 이름만 보내는 사람 화면 기준으로 박아 넣으면 문구는 영어인데
  이름만 한글인 줄이 됩니다. 그래서 `LocalName`(= `(locale) => string`)으로 넘깁니다.

## 친구

**같은 모임에서 만난 사람에게만** 요청을 보낼 수 있습니다. 사람을 찾는 화면이 없는 것은 일부러입니다 —
얼굴을 본 사이에서만 이어지게 두려는 것이고, 덕분에 아이디를 넣어 남이 회원인지 떠보는 일도 막힙니다
(요청 라우트가 사람을 찾아보기 **전에** 같은 모임 여부를 보므로, 없는 아이디도 같은 403이 돌아갑니다).

- **관계는 늘 쌍방**입니다. `friendships` 테이블은 한 쌍에 한 줄이고, 늘 `user_a < user_b` 순으로 넣습니다
  (순서는 `lib/db/friends.ts`의 `pair()` 한 곳에서만 정합니다). 두 사람이 같은 순간에 서로에게 요청하면
  기본키가 부딪히고, 그 자리에서 수락으로 바뀝니다 — 서로 원한 게 확인된 셈이라 맞는 결과입니다
- **거절·요청 취소·친구 끊기는 셋 다 줄을 지웁니다.** 상태를 남기지 않으므로 나중에 다시 요청할 수 있고,
  누구에게도 "거절당했어요"가 가지 않습니다
- 수락 권한은 별도 조회가 아니라 `UPDATE ... WHERE status='pending' AND requested_by <> me` 안에 있습니다.
  두 번 눌러도 두 번째는 0줄이라 알림이 겹치지 않습니다
- **친구 소식은 인앱 알림 한 줄뿐입니다** (`insertInAppNotice`). 카톡도 푸시도 보내지 않습니다 —
  친구가 열 명이면 각자 모임에 들어갈 때마다 폰이 울리고, 그러면 사람들이 알림부터 끕니다.
  이 경로에는 `sendNotice`가 아예 없어서 구조로 지켜집니다
- **친구를 모임에 대신 넣을 수 있습니다** (`POST /api/posts/<id>/participants`). 동의를 묻지 않고 바로
  들어가고, 넣긴 사람에게 알림이 갑니다 — 본인이 나가기를 누르면 그만입니다.
  조건: 친구일 것 · 넣는 사람도 그 모임 참가자일 것 · 지난 모임이 아닐 것 · 중복 아닐 것 · 정원이 남을 것
- **비공개(link) 모임은 참가 알림을 보내지 않습니다.** 링크를 받은 사람만 알아야 하는 모임인데
  "누가 어디에 갔다"가 나가면 그 사실이 새어 나갑니다. 대신 만들 때 **친구를 전부 고른 채로** 띄우고,
  뺄 사람만 빼서 고른 친구에게만 링크 알림을 보냅니다 (참가자로 넣지는 않습니다).
  매주 반복은 첫 회차에만 초대가 나가 헷갈리므로 그때는 피커를 숨깁니다
- **접속 중인 친구는 친구에게만** 보입니다. `/api/presence`(관리자 전용)는 그대로 두고,
  `/api/friends`가 내 친구 범위에서만 계산합니다. 마지막 접속 시각 자체는 내보내지 않고
  접속 중일 때의 `secondsAgo`만 나갑니다
- 화면은 **알림 탭 맨 위의 "친구" 줄 → `/friends`** 입니다. 요청 수 배지는 알림 응답에 실려 오므로
  요청을 더 보내지 않습니다. 친구 요청도 알림 줄을 만들기 때문에 벨 배지는 손대지 않아도 맞습니다

알림 종류(`notifications.kind`)는 타입 없는 문자열이라 오타 하나면 조용히 안 눌리는 줄이 됩니다.
쓰는 쪽도 읽는 쪽도 **`lib/notif-kinds.ts`의 `NOTIF`를 거칩니다.** 이 파일은 DB를 import하지 않습니다 —
알림 화면이 클라이언트 컴포넌트라 `lib/db/*`에 두면 drizzle과 PGlite가 브라우저 번들에 딸려 옵니다.

## 앱 푸시 알림 (PWA, 선택)

카카오톡 알림과 **나란히** 나갑니다 — 카톡 메시지 동의를 거부한 사람도 받을 수 있고,
홈 화면에 설치한 사람은 앱 아이콘 배지로 봅니다. 카톡을 대체하지 않습니다.

1. VAPID 키 한 쌍을 만듭니다 (서버가 "내가 그 사이트 맞다"고 서명하는 데 씁니다):
   ```bash
   npx web-push generate-vapid-keys
   ```
2. 환경변수 세 개 (로컬 `.env.local` + Vercel):
   - `NEXT_PUBLIC_VAPID_PUBLIC_KEY` — 브라우저가 구독할 때 쓴다 (빌드 시 번들에 박히므로 **바꾸면 재배포 필요**)
   - `VAPID_PRIVATE_KEY` — 서버 서명용
   - `VAPID_SUBJECT` — `mailto:연락처`
3. `npm run db:push` (push_subscriptions 테이블)
4. 사용자는 **프로필 → 앱 푸시 알림**에서 켭니다.

**아이폰은 홈 화면에 추가해야만 켤 수 있습니다.** iOS는 설치된 PWA에서만 웹 푸시를 지원해서,
사파리 탭으로 열어둔 상태에서는 `PushManager` 자체가 없습니다. 그 경우 화면에 설치 안내가 뜹니다.

개발 중에는 실제 기기로 발송하지 않습니다 — 진짜로 보내보려면 `PUSH_IN_DEV=1`.
(`.env.local`에 실제 `DATABASE_URL`을 넣어 두면 로컬 테스트가 진짜 구독자에게 나갑니다.)

**VAPID 키를 바꾸면 기존 구독이 전부 깨집니다.** 구독은 만들 때 쓴 키 쌍에 묶여 있어서,
다른 비밀 키로 서명하면 푸시 서비스가 403으로 거절합니다. 한 번 정한 키는 그대로 두세요.

키가 없으면 기능 전체가 조용히 꺼집니다 (프로필에 항목이 아예 안 보입니다).
구독은 기기마다 한 줄이고, 발송이 404/410으로 실패하면 그 줄을 지웁니다 — 구독은 조용히 만료됩니다.

## 디자인 파일을 새로 받았을 때

시안 파일(`app/globals.css`)은 통째로 갈아끼우는 일이 잦습니다. 그때 함께 지워지던
수정들은 **`app/overrides.css`** 로 옮겨두었습니다. `layout.tsx`가 globals 다음에 불러오므로
시안이 무엇을 정의하든 이쪽이 이깁니다.

```bash
cp ../handoff/globals.css app/globals.css   # 1. 시안 덮어쓰기
npm run css:fix                             # 2. hover 규칙 감싸기
```

`overrides.css`는 건드리지 않습니다. 지금 담고 있는 것:

- `main.container` 세로 여백 — 없으면 페이지 맨 끝 내용이 떠 있는 탭바 뒤로 들어갑니다
- 스크롤 시 상·하단 바 감추기 (데스크톱 좌측 레일에서는 끔)
- 프로필 사진 (탭바 아바타 이미지, 프로필 화면 사진 고르기)
- 홈 화면에 추가 안내의 단계 목록

**`npm run css:fix`** (= `scripts/no-touch-hover.mjs`)는 globals.css의 `:hover` 규칙을
`@media (hover: hover)`로 감쌉니다. iOS는 hover 스타일이 있는 요소를 "첫 탭은 hover,
두 번째 탭이 실행"으로 다뤄서, 감싸지 않으면 탭바 버튼을 두 번 눌러야 합니다.
이것만은 덧붙이기로 안 되고 시안의 규칙 자체를 감싸야 해서 스크립트로 뒀습니다.
여러 번 돌려도 안전합니다(이미 감싼 건 건너뜁니다).

### 샌드박스 키로 먼저 테스트하기

프로덕션 키 승인 전에 샌드박스 키로 연동 코드를 검증할 수 있습니다:

```
AMC_API_BASE=https://api.sandbox-amctheatres.com/v2
AMC_VENDOR_KEY=<샌드박스 키>
AMC_THEATRE_ID=<샌드박스 극장 ID>   # GET /v2/theatres 로 조회 (테스트 극장 5곳)
```
